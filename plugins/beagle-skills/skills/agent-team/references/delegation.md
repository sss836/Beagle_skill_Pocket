# 派发格式与任务变体

派发时按任务填写以下字段，不向子 agent 发送未填写的占位文本：角色、具体目标、原始输入与必要背景、负责范围及允许修改的文件、依赖与已确定决策、领域技能路径（如有）、交付物位置、验收标准。汇报实际完成事项、可定位证据和剩余问题。

- 产品方案：A 分析需求与约束；B 编写方案与实现材料；C 从用户场景核查遗漏和前后矛盾。主 agent 决定取舍。
- 软件修复：A 定位问题；B 修改被分配的模块；C 复现原问题并检查受影响行为。按风险安排必要测试。
- 文献对比：A、B 分别调查独立来源或方案；C 核对引用和主张；主 agent 综合证据。无需修改就不安排实现角色。
- 论文汇报：A 提取论文主张和图证；B 使用可用的论文汇报与演示文稿技能制作；C 按原文和最终渲染检查。等待原始论文，不能编造内容。

验收需要真实产物。没有产物、未执行检查或仅报告“看起来没问题”，不足以作为通过证据。
